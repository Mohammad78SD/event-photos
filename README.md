# Event Photos

Guests at an event scan a QR code and upload photos from their phones to a shared album, with a live projector wall.

## What it does

**Guest flow** (three screens, phone-first):

1. Scan the QR code (a printable A6 table card with the event QR is generated by the app).
2. Enter a name and phone number (unverified, used for attribution, see [decisions](docs/DECISIONS.md)).
3. Pick photos and upload. Progress is shown per file, with an optional caption.

**Owner / couple dashboard** (login required): create and edit events, copy links, print the table card, and see guests.

**Approval:** moderation is per guest, not per photo. A new guest's first batch shows up as one card in a queue; one tap approves that guest and their later uploads publish directly. Guests always see their own photos, with a "pending" badge. A secret **moderator link** lets a helper approve without a login.

**Album:** a gallery of approved photos; individual photos can be hidden or deleted.

**Live projector wall:** a full-screen slideshow (`/e/<slug>/live/`) that polls for new approved photos and shows the event QR code.

**Owner-only full download:** the owner can request a ZIP of the album, built in the background by Celery and downloaded through a tokenised link. The moderator link does not grant this.

**Kill switches and limits** (all per event, verified in the code):

- Close uploads (`is_open`), the upload and guest pages return 404 when closed.
- Turn off gallery sharing (`gallery_shared`), everyone drops to their own photos only and the projector wall empties.
- Require approval (`require_approval`).
- Max file size (`max_file_mb`), max files per batch (`max_files_batch`), and an overall storage quota (`quota_gb`) that rejects uploads past the ceiling.
- Redis-backed rate limits per guest and per IP.
- Server-side MIME sniffing (`python-magic`); only images are accepted (JPEG, PNG, WebP, HEIC/HEIF). No videos.

## Tech stack

- Python 3.12, Django 5.1, Django REST framework (upload endpoint)
- PostgreSQL 16, Redis (rate limiting), Celery (thumbnails/previews, ZIP export)
- Docker Compose, nginx (serves media via `X-Accel-Redirect` after Django's visibility check), gunicorn in production
- Tailwind CSS and esbuild for assets; Uppy (`@uppy/core`, `@uppy/xhr-upload`) and `browser-image-compression` on the client
- Pillow and pillow-heif for image processing, segno for QR codes
- Uploads are one request per file (3 in parallel). Photos are downsized to 2560px on the phone before upload by default, with an "original quality" toggle. There is no chunked/resumable upload.

## Persian-first UI

The interface is Persian and right-to-left (`lang="fa"`, `dir="rtl"`, Asia/Tehran time zone, Jalali date display), with Latin display type for the names. See [docs/DESIGN.md](docs/DESIGN.md).

## Architecture and key decisions

Full reasoning is in [docs/DECISIONS.md](docs/DECISIONS.md); design in [docs/DESIGN.md](docs/DESIGN.md); production setup in [docs/DEPLOY.md](docs/DEPLOY.md).

- **Resize on the client, never recompress on the server.** The uploaded file is the archive copy, so there is one lossy step instead of two, and uploads finish on bad venue networks.
- **No SMS OTP.** An unverified phone number is for attribution, not security; OTP would add cost and friction. A `require_otp` flag exists for later.
- **Per-guest moderation.** Per-photo approval does not scale for people busy at their own event; per-guest keeps "nothing unvetted is public" at a fraction of the effort.
- **An always-open link needs other controls:** approval queue, unguessable slug, rate limits, MIME sniffing, quota, and the gallery kill switch.
- **No videos.** They are the disk risk and cannot be shrunk on the client.
- **Django templates, not an SPA.** Three screens on a phone with a bad network; less to download and deploy.

## Running locally

Requires Docker and Node.js.

```bash
cp .env.example .env          # set DJANGO_SECRET_KEY
npm ci && npm run build       # builds static/dist (CSS + JS)
docker compose up -d --build
docker compose exec app python manage.py migrate
docker compose exec app python manage.py createsuperuser
docker compose exec app python manage.py collectstatic --noinput
```

The app is at http://localhost:8080 (via nginx, which also serves access-controlled media) and http://localhost:8000 (Django dev server). Log in at `/accounts/login/`, create an event at `/create/`, then open `/e/<slug>/`.

## Tests

Tests need PostgreSQL, Redis is not needed (fakeredis), and the `libmagic` system library. With a Postgres instance available:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements/dev.txt
npm ci && npm run build        # two tests check the built asset URLs
export DJANGO_SECRET_KEY=test DEBUG=False DATABASE_URL=psql://user:pass@localhost:5432/dbname
pytest -q
```

Last run: **90 tests, all passing**. CI (`.github/workflows/ci.yml`) runs the same on every push and pull request.
